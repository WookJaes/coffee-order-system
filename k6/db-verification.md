# k6 DB 정합성 검증 결과

## 기록 기준

이 문서는 k6 실행 후 MySQL에서 확인한 데이터 정합성만 기록한다. k6 응답시간·오류율·threshold는 [k6 부하 테스트 결과](results.md)에서 관리한다.

필수 검증 대상은 동일 사용자 동시 주문이다. 최종 잔액은 `초기 잔액 + CHARGE 합계 - USE 합계`와 일치해야 하고 음수가 아니어야 하며, 성공 주문 수·`USE` 이력 수·Outbox 수는 같아야 한다.

## 1회차: 초안 검증

**실행일:** 2026-07-16

**판정:** FAIL

| 항목 | 실제 값 | 기대 값 | 판정 |
| --- | --- | --- | --- |
| 대상 사용자 | ID 10 | 동일 사용자 1명 | PASS |
| 충전 금액 | 100,000P | 100,000P | PASS |
| 성공 주문 수 | 5 | 5 | PASS |
| `USE` 이력 수 | 5 | 성공 주문 수와 동일 | PASS |
| Outbox 수 | 5 | 성공 주문 수와 동일 | PASS |
| 최종 잔액 | 95,500P | 77,500P | FAIL |
| 음수 잔액 | 없음 | 없음 | PASS |
| `USE.balance_after` | 5건 모두 95,500P | 주문마다 누적 차감 잔액 | FAIL |

4,500P 주문 5건이 HTTP 201로 모두 성공했지만, 기대 잔액 `100,000 - (4,500 × 5) = 77,500P`보다 18,000P 높았다. 즉 4건의 차감이 유실됐다. 주문·`USE`·Outbox 수만 일치하므로 이 항목만으로 정합성을 PASS로 판정할 수 없다.

### 다중 사용자 실행분 참고

ID 11~18은 Load·Stress·Spike 사이에 테스트 데이터를 재사용했으므로 시나리오별 결과가 아니라 합산으로만 확인했다. 최종 잔액 9,767,000P는 `CHARGE 12,800,000P - USE 3,033,000P`와 일치했고, `PAID` 주문·`USE` 이력·Outbox는 각각 674건이었다. 음수 잔액은 없었다.
